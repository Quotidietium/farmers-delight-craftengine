# 偏差表 7 项处置决策材料

> 目的：为「关闭为永久偏差」或「指定继续迭代」提供逐项论证。
> 结论先行：7 项的限制层均在**原版客户端渲染 / 原版注册表 / 原版世界生成**，
> 服务端插件（含 CraftEngine）在架构上无法直达；每项已有等效补偿。
> 逐项评估「强行继续」的路径后，无一具备合理收益/成本比。

## 逐项论证

### ① 舒适/滋养无 HUD 图标（补偿：actionbar 开始/进度提示）
- **根因**：HUD 图标是客户端渲染层（原版药水图标绘制管线）。药水效果类型注册在
  原版注册表，Paper 的 `RegistryEvent` 只开放了少数类别（附魔/药水效果类型在
  Paper 1.21 未开放自定义注册；我方 Bootstrap 已用它注册背刺附魔——附魔开放而
  效果不开放）。
- **强行继续**：资源包层无法凭空造 HUD 元素；客户端 mod 才能画。无服务端路径。
- **判定**：永久偏差。

### ② 告示牌聊天输入（补偿：逐行输入 done/cancel）
- **根因**：原版告示牌编辑 GUI 是客户端界面；CE 告示牌为文本展示实体方案。
- **强行继续**：无 API 在服务端打开原版签名编辑屏（该屏仅客户端为真实告示牌
  方块弹出）。
- **判定**：永久偏差（当前聊天输入功能完整：4 行文本+染色+渲染）。

### ③ 原版汤类堆叠 16（补偿：FD 碗餐不受影响）
- **根因**：堆叠上限是物品组件（`max_stack_size`），原版物品（蘑菇煲等）的组件
  由客户端与服务端共同按注册表默认值校验；服务端插件改原版物品默认组件无公开 API。
- **强行继续**：数据包可给**新物品**设组件，不能改原版物品定义；反射改注册表
  需要跨客户端-服务端一致性（客户端不认会即刻回退/刷出异常）。
- **判定**：永久偏差。

### ④ 村庄堆肥小屋未注入（补偿：野生作物覆盖获取途径）
- **根因**：mod 用 Mixin 改 `StructurePool` 运行时注入 5 种 NBT 小屋。Paper 世界
  生成结构池修改需在区块生成前注册（Paper 结构 API 不支持向已有池追加模板）；
  REF 也未做此功能。
- **强行继续**：数据包可整体替换村庄结构集（巨大工程且与原版地图生成强耦合），
  或世界生成钩子逐区块扫描替换（高脆弱、高成本）。
- **判定**：永久偏差（获取途径已由野生作物+沃土循环覆盖）。

### ⑤ 绳子攀爬速度模拟 —— **结论改写（1.4.1 复审）：mod 无此功能，非偏差**
- **仲裁**：mod `RopeBlock extends PaneBlock`（settings=brown_carpet 无碰撞），
  全源码无 climbable 标签/实现/数据包引用——**mod 绳子本来就不可以攀爬**。
  我方 1.0.0 的「每 tick 上浮 0.13/潜行悬停」是移植时额外添加的功能，并非未复现差距。
- **处置**：保留现有实现（对用户是纯增益，移除反而造成体验回退）；偏差表⑤关闭。
- **迁移说明**：此前评估的「绳子→CE 方块迁移」不再必要（其唯一动机 climbable 不成立，
  mod 对应物本就是不可攀的 PaneBlock）。

### ⑥ 手持煎锅按住右键检测（补偿：actionbar 进度+完成音效）
- **根因**：mod 用「按住右键持续使用」（`use` 每 tick 回调）——Paper 只有
  `PlayerInteractEvent`（按下/连发）与 `PlayerItemHeldEvent`（换手），无持续
  使用状态查询；1.21 的 `player.getCurrentActionPoint`/使用滴答不可靠且无事件。
- **强行继续**：可以用「右键触发+计时任务模拟持续使用」的更精细状态机（现有
  SkilletHand 已是此方案的实现），无法更接近原版手感。
- **判定**：永久偏差（现有实现已是服务端能做到的上限）。

### ⑦ 附魔台获取背刺（补偿：刀具已带 enchantable，铁砧+附魔书可用）
- **根因**：附魔台候选列表是客户端-服务端同步的原版逻辑（服务端算好发给客户端
  显示）；背刺是自定义附魔，进附魔台候选需要附魔的 `treasure/enchantable` 标签
  体系为原版附魔台识别——数据包附魔（1.21）可注册进附魔台，但我方背刺经 Paper
  RegistryEvent 注册（插件附魔），其 enchantable 分组不被原版附魔台数据包逻辑识别。
- **强行继续**：改用 **1.21 数据包附魔**重做背刺（`enchantment` JSON + registry），
  可进附魔台。成本：背刺逻辑迁移到数据包附魔框架（伤害计算走事件重写），
  与现有插件附魔并存或替换（替换=破坏已发放的背刺附魔存档）。
- **判定**：技术上可实现的中型迭代（约 200-400 行）；功能价值取决于你服务器
  是否重度使用附魔台。建议：若要，作为 1.4.0 独立迭代。

## 处置建议汇总

| # | 项目 | 建议 |
|---|---|---|
| ①②③④⑥ | 无服务端路径或已达上限 | 关闭为永久偏差 |
| ⑤ 绳子攀爬 | 架构迁移可达但成本高、手感仍非原版 | 关闭；如坚持列为独立大迭代 |
| ⑦ 附魔台背刺 | 数据包附魔可实现 | 关闭或列为 1.4.0（二选一） |

我按你的决定执行（关闭=整理最终收敛报告结束主线；继续=按上表路径开迭代）。
