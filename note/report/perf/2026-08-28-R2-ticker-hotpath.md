# R2 — GameTicker 调度热路径（分段采样 + A/B 开关）

> 日期：2026-08-28 ｜ 环境：smoke 服务器（Papo 1.21.11 + CE 26.7.4）
> 负载：400 个机制对象（80 炉灶 / 80 堆肥 / 80 沃土耕地+小麦 / 80 篮子 / 80 家具锅+煎锅），
> 强制加载区块，采样 25 秒（每秒读一次分段累计，每脉冲 10 游戏刻）。

## 量化基础设施（本轮新增，benchmark/）

- **GameTicker 分段采样器**：零分配累计计数器（total/家具/炉灶/篮子/堆肥/作物土壤 6 段），
  常驻开销 ~12 次 `nanoTime`/脉冲（<0.5µs），`/bench tick <秒>` 采样输出 mean/p95。
- **`/bench load <n>`**：批量放置机制对象并按玩家路径注册 ChunkIndex（静态 API 不触发
  CE place 事件，bench 显式补注册——与玩家放置终态一致）。
- **A/B 开关**：`-Dfd.legacy-tick=true` 在同一构建上恢复 R2 前热路径（无 chunk-loaded
  早退 / 无堆肥预门控 / 锅库存总是重读），保证 before/after 除目标优化外完全同构。

## 优化内容

1. **堆肥预门控**：随机掷骰数学前置（可达概率上限 0.74×3/4096×10≈0.54%），
   99.5% 的调用免做 3×3×3=27 块邻域扫描。两阶段独立掷骰 `P = maxGate × (chance/maxGate)
   = chance`，与原单次掷骰**严格等概率**。
2. **家具循环 chunk-loaded 早退**：卸载区块上的家具跳过（tickPot 的库存读取、CE 查询全免）。
3. **锅库存条件重读**：库存快照仅在存在相邻漏斗时重读（漏斗会在自己的 tick 修改 CE
   库存，无条件复用会覆盖漏斗插入——保持正确性前提下的省略；无漏斗时省一次全量
   反序列化/反射读取）。
4. **soilIndex 遗留条目自愈**：rich_soil_farmland 条目（行为接管后不再需要）被清理。

## 结果（ns/脉冲，400 对象，25 秒采样 mean）

| 段 | before (legacy) | after (优化) | 变化 |
|---|---|---|---|
| **total** | **9,797,035** | **6,181,144** | **1.58x** |
| stove | 3,122,811 | 3,609,792 | 噪声（无本轮改动，见下） |
| **compost** | **4,673,017** | **226,356** | **20.7x** |
| basket | 1,447,360 | 1,517,012 | 持平 |
| crop+soil | 146,624 | 164,980 | 持平 |
| furniture | 75,136 | 154,832 | 噪声（两轮均有 chunk-loaded 路径差异，绝对值 <0.2ms） |

原始数据：`R2-before-raw.txt` / `R2-after-raw.txt`。

## 解读与红线

- **堆肥预门控是本轮收益核心**（总耗时 -46%），数学等价性保证结果分布不变。
- stove/basket/crop+soil 三段无本轮优化，均值波动（+15%/-5%）为跨进程噪声；
  stove+basket 合计 5.1ms/脉冲是下一轮（R3）的明确目标。
- **正确性守护**：锅库存重读保留漏斗邻接条件，杜绝快照覆盖漏斗插入的物品丢失。
- 红线核验：非 bench 窗口 0 ERROR；默认路径（无 legacy 参数）行为与 1.2.0 发布版一致；
  预门控概率等价已证明；ChunkIndex 数据/恢复语义未动。
- 已知测试基建问题（不影响生产）：`/bench load` 的静态放置绕过 CE place 事件，
  bench 显式补注册；真实玩家放置路径不受影响。

## 附带发现（转 R3+）

- ChunkIndex.entries() 每次调用反序列化 chunk PDC long[] 并分配 List/Location，
  每 chunk 每脉冲 4-5 次——缓存+脏标记是 R3 的核心素材。
- tickStove 对空炉灶仍做完整 isHeated（多次 getRelative + CE 查询）——快路径重排。
