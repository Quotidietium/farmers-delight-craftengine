# 1.2.1 — 性能优化轮（R1-R3）

> 三轮性能优化全部以「结果一致」为红线：R1 带 40,000 次模糊输入 parity gate，
> R2/R3 用 `-Dfd.legacy-tick` 同构建 A/B 开关采样对比。量化程序在 `benchmark/`
> （服务器内 `/bench` 命令），报告在 `note/report/perf/`。

## R1 配方匹配（benchmark + FDRecipes）

- 切割配方 O(1) 索引（input→配方、input→工具集）、烹饪配方 size 分桶；
- 签名 memo 缓存实测负优化（344k vs 250k）已回退并记录在案；
- 结果：切割 3.85x/4.12x、toolsForInput 8.55x、烹饪 1.19x/1.28x；parity 0 mismatch。

## R2 ticker 热路径（GameTicker）

- 常驻分段采样器（6 段，<0.5µs/脉冲）+ `/bench tick|load` 量化命令；
- 堆肥预门控（两阶段掷骮严格等概率，99.5% 调用免 27 块扫描）：**20.7x**；
- 家具循环 chunk-loaded 早退；锅库存仅在漏斗邻接时重读（防快照覆盖漏斗插入）；
- 400 对象 A/B：总耗时 **9.80→6.18ms/脉冲（1.58x）**。

## R3 ChunkIndex 缓存 + 炉灶/篮子快路径

- ChunkIndex.entries 按区块缓存（WeakHashMap，写失效）——原每脉冲每区块 4-5 次
  全量 PDC 反序列化；
- 空炉跳过每脉冲 2 次全零 PDC 字符串写（读取等价）；满篮（无空槽无半叠）跳过
  实体邻域扫描；
- 同世界 A/B（~560 对象）：总耗时 **11.16→5.18ms/脉冲（2.15x）**，炉灶 2.31x。

## 累计

| 路径 | 提速 |
|---|---|
| ticker 总耗时（400-560 对象） | ~2x（11.2→5.2ms/脉冲） |
| 堆肥 tick | 20x |
| 切割配方匹配 | ~4x |
| 工具集查询 | ~8.5x |

## 兼容性

- 所有优化在默认路径启用，`-Dfd.legacy-tick=true` 可随时回退旧行为（诊断用）；
- ChunkIndex 存储格式、配方数据、交互语义均无变化；升级仅需替换 jar。
