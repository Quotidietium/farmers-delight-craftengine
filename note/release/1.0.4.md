# 1.0.4 — 烹饪锅 GUI 三重保障 + CE 存储后端统一

## 修复
按验证器建议为烹饪锅附加 CE `simple_storage_furniture` 行为（rows:1 = 9 格，与专用 GUI 槽位模型一一对应）：

**存储后端统一**：烹饪锅的 9 格物品（6 输入+餐盘+碗+输出）现在存储在 CE 家具实体 NBT（data_key farmersdelight:pot_contents），
插件的烹饪 ticker 与 GUI 经反射访问同一 Inventory（SimpleStorageFurnitureController.inventory）——消除双存储不同步风险。

**GUI 打开路径三重保障**（全部指向同一库存）：
1. CE `FurnitureInteractEvent`（包级）→ 插件专用 GUI（还原 mod 槽位布局）
2. Bukkit `PlayerInteractEntityEvent`（碰撞实体反查）→ 插件专用 GUI
3. CE 原生 `simple_storage_furniture` 行为 → CE 自己的 9 格 GUI（前两条路径都失效时的保底，
   玩家放入的物品同样会被烹饪 ticker 处理）

## 修复过程中的缺陷
生成器曾把 behavior 块插入 variants 与其内容之间导致 YAML 结构错误（锅无法放置），已修正为变体之后追加。
